# Хранение тестов

Как загруженный JSON-файл превращается в строку базы и как её читают. Формат самого файла описан в [TEST-FORMAT.md](./TEST-FORMAT.md) — этот документ про то, что происходит после загрузки.

## 1. Решение

Версия теста — **неизменяемый документ**. Опубликованную версию никто не редактирует: повторная загрузка того же `id` создаёт новую версию. Поэтому вопросы и варианты лежат целиком в JSON-колонке `Test.content`, а не в отдельных таблицах.

Отдельных таблиц `TestQuestion` / `TestOption` больше нет — они были удалены миграцией `20260905183000_store_test_content_as_json`.

Почему так:

- по частям документа никто не ходит запросами — все читатели грузят тест целиком;
- нормализация не давала ссылочной целостности: у `Answer` никогда не было внешних ключей на вопросы и варианты, проверки всегда жили в коде;
- разложив документ по таблицам, мы получали внутренние `cuid`, а потом на каждом чтении переводили их обратно в авторские `id` — работа ради самой себя;
- рядом лежала колонка `sourceJson` с полной копией документа, то есть два источника правды, которые ничто не сверяло;
- каждое новое поле вопроса требовало миграции (как это было с `hint`).

**Файловое хранилище рассматривалось и отклонено.** Оно ломает атомарность импорта (файл записан, вставка упала), требует согласованного бэкапа двух систем, не переживает эфемерный диск контейнера и не даёт ничего сверх `jsonb`.

## 2. Что происходит при импорте

`POST /api/v1/admin/tests/import`, тело — `multipart/form-data` с полем `file`.

### Проверки на входе

| Проверка | Ответ при провале |
| --- | --- |
| роль `ADMIN` | 401 / 403 |
| поле `file` присутствует и это файл | 400 `FILE_REQUIRED` |
| размер ≤ 1 МБ | 413 `FILE_TOO_LARGE` |
| `JSON.parse` проходит | 422 `INVALID_JSON` |
| JSON Schema | 422 `VALIDATION_ERROR` |

`VALIDATION_ERROR` возвращает массив `details`: путь до поля (`/questions/0/options`), код и текст ошибки. Сверх схемы `validateTestDocument` проверяет то, что JSON Schema выразить не может: повторяющиеся `id` вопросов, повторяющиеся `id` вариантов внутри вопроса, существование `correctOptionId` в `options` (для вопросов с выбором).

### Запись

`createTestDraft` делает два запроса и **один** `INSERT`:

1. `findFirst` по `stableId` с сортировкой по `version desc` — узнать текущую версию;
2. `buildTestContent` нормализует вопросы: `points` по умолчанию `1`, отсутствующие `hint` и `explanation` становятся явным `null`;
3. `prisma.test.create` — одна строка.

Вложенных записей нет: раньше это был `1 + N + M` инсертов во вложенной транзакции.

Тест сохраняется как `DRAFT`. Он никому не назначается и детям не виден до нажатия «Publish».

## 3. Что лежит в базе

Колонками остаётся то, по чему фильтруют и сортируют; содержимое — в JSON.

```
Test
  id             cuid
  stableId       "science-plants-01"   -- id из файла
  version        2                     -- @@unique([stableId, version])
  title, description, subject, grade, passPercentage
  status         DRAFT | PUBLISHED | ARCHIVED
  questionCount  1                     -- денормализовано, чтобы списки не парсили JSON
  content        jsonb
```

```json
{
  "schemaVersion": "1.0",
  "questions": [
    {
      "id": "q1",
      "type": "choice",
      "text": "Что нужно растению для фотосинтеза?",
      "points": 1,
      "hint": "…markdown…",
      "explanation": "…markdown…",
      "options": [{ "id": "a", "text": "Свет" }],
      "correctOptionId": "a"
    },
    {
      "id": "q2",
      "type": "input",
      "text": "На сколько сантиметров вырос росток?",
      "points": 1,
      "hint": null,
      "explanation": null,
      "correctAnswers": ["2.3"]
    }
  ]
}
```

Контент, записанный до появления типов вопросов, не содержит `type`: `readTestContent` считает такие вопросы `choice`, поэтому старые строки не мигрируются.

`title`, `subject`, `grade` в `content` не дублируются. Исходный файл целиком не хранится: при необходимости он собирается из колонок и `content`.

Ответы ребёнка ссылаются на авторские идентификаторы:

```
Answer
  attemptId
  questionId   "q1"   -- id из файла, не id базы
  optionId     "a"    -- вопрос с выбором
  value        "2,3"  -- вопрос с вводом: строка как её ввёл ребёнок, без пробелов по краям
```

Заполнено ровно одно из `optionId` и `value` — это CHECK-ограничение `Answer_option_or_value_check`. Введённая строка хранится как есть, а не нормализованной: разбор показывает ребёнку и администратору именно то, что было введено. Вердикт в строке не хранится — его вычисляет `isAnswerCorrect` по неизменяемой версии теста.

Версия неизменяема, поэтому такая ссылка валидна навсегда.

## 4. Как это читается

Единственная точка входа — `readTestContent(test.content)` из `src/lib/test-content.ts`.

| Кто | Что берёт |
| --- | --- |
| `serializeAttempt` | вопросы, варианты, `hint`; `correctOptionId` (или `correctAnswer` — первый из `correctAnswers`) и `explanation` — только для отвеченных вопросов или сданной попытки; у каждого ответа — `isCorrect` |
| сохранение ответа | ищет вопрос и вариант в `content`, пишет в `Answer` авторские id; для ввода — непустую строку до 200 символов |
| подсчёт баллов и звёзд | `isAnswerCorrect` из `src/lib/grading.ts`: `optionId` против `correctOptionId` или `value` против `correctAnswers` |
| админский preview | восстанавливает `isCorrect` каждого варианта из `correctOptionId`, для ввода показывает `correctAnswers` |
| списки (дашборд, библиотека) | `questionCount` из колонки, `content` не трогают |

`readTestContent` проверяет форму неглубоко: JSON пишем мы сами после валидации, перепроверять каждое поле незачем. Битая строка деградирует до теста без вопросов, а не роняет запрос.

## 5. Что сделать в будущем

Спорные места и известные пробелы. Ни одно не блокирует текущую работу.

### 5.1. Гонка версий при импорте

`createTestDraft` читает последнюю версию отдельным запросом, а потом вставляет. Два одновременных импорта одного `stableId` прочитают одно и то же значение и попробуют вставить одинаковую версию. `@@unique([stableId, version])` это поймает, но ошибку Prisma наружу никто не обрабатывает — админ получит 500 вместо внятного сообщения.

Чинится либо ретраем на `P2002`, либо вычислением версии внутри одного `INSERT ... SELECT`. При одном администраторе неактуально.

### 5.2. `Attempt.testVersion` ни на что не влияет

Поле записывается, но нигде не участвует в выборе версии: `Assignment.testId` указывает на конкретную строку `Test`, то есть уже на конкретную версию. Публикация новой версии сама собой не подхватывается — нужно новое назначение.

Требует продуктового решения: назначать на `stableId` и брать последнюю опубликованную версию, либо переносить назначения при публикации, либо честно убрать поле как избыточное.

### 5.3. `id` в опубликованной версии менять нельзя

На `id` вопросов и вариантов ссылаются строки `Answer`. Это соглашение, а не ограничение схемы: ничто не мешает залить новую версию, в которой `q1` означает другой вопрос — исторические ответы тихо станут неверно интерпретированными.

Проверить это автоматически нельзя, но можно предупреждать при импорте, если у новой версии изменился набор `id` при совпадающем `stableId`.

### 5.4. Нет ссылочной целостности у `Answer`

Осознанно: её не было и в нормализованной схеме. Валидация живёт в обработчике сохранения ответа — вопрос и вариант ищутся в `content` текущей версии, иначе 422. Если появится аналитика вида «какой вопрос чаще заваливают», `GROUP BY Answer.questionId` будет работать, но текст вопроса придётся доставать из `content`, а не джойном.

### 5.5. Исходный файл не сохраняется

`sourceJson` удалён. Реэкспорт собирается из колонок и `content`, то есть байт-в-байт исходник (форматирование, порядок ключей, комментарии) не восстановится. Если это когда-нибудь понадобится — решать отдельно; в разделе «Открытые решения» [API-DRAFT.md](./API-DRAFT.md) на эту тему было объектное хранилище, от которого мы отказались.

### 5.6. Картинки в Markdown идут с внешних хостов

`hint` и `explanation` рендерятся через `react-markdown`. Сырой HTML выключен, но синтаксис `![](https://…)` работает, и картинка грузится с чужого домена. Ни allowlist, ни CSP на это сейчас нет. Для семейного сервиса с одним админом это приемлемо, но стоит помнить.

### 5.7. Битый `content` не логируется

`readTestContent` при неожиданной форме молча возвращает пустой список вопросов. Ребёнок увидит «тест без вопросов», а в логах не будет ничего. Стоит добавить хотя бы `console.error`.

### 5.8. Правила сравнения введённых ответов действуют задним числом

Вердикт по вопросу с вводом не сохраняется, а вычисляется при каждом чтении. Если поменять нормализацию в `src/lib/grading.ts`, баллы и звёзды уже сданных попыток не изменятся (они записаны в `Result` и `TestReward`), но разбор старой попытки может показать другой вердикт. Если правила начнут меняться, стоит сохранять `Answer.isCorrect` в момент проверки.

### 5.9. `GET /api/v1/me/tests/:testId` больше не используется

После удаления промежуточной страницы теста фронтенд к этому endpoint не обращается. Он остаётся рабочим и задокументирован в [API-DRAFT.md](./API-DRAFT.md) — надо либо задействовать, либо убрать.
