# Наборы тестов

Набор — именованная группа тестов, которую собирает администратор: «Дроби», «Неделя 1». Наборы нужны, чтобы у ребёнка списки тестов не сливались в одну ленту, и чтобы назначать несколько тестов одной кнопкой.

## Правила

- Тест входит максимум в один набор. Членство хранится по `Test.stableId` (`TestSetItem.stableId` — первичный ключ), поэтому новые версии теста остаются в своём наборе.
- Добавление теста в другой набор переносит его; API отвечает `movedFrom` с названием прежнего набора.
- В набор можно положить черновик: он будет сгруппирован сразу после публикации. Назначить неопубликованный тест нельзя.
- Удаление набора не трогает тесты и назначения — они только перестают быть сгруппированы. Удаление последней версии теста убирает его из набора.
- Наборы сортируются по имени с естественным порядком чисел: «Неделя 2» раньше «Неделя 10». Внутри набора сохраняется обычный порядок списка: сначала незавершённые, затем не начатые, затем пройденные.

## Назначение набора

`POST /api/v1/admin/test-sets/:id/assign` с `{ "childIds": [...] }` или `{ "groupId": "..." }` раздаёт самую новую опубликованную версию каждого теста набора:

- ребёнку — только тесты его класса, как и при одиночном назначении; остальные попадают в счётчик `otherGrade`;
- группе — все тесты, класс не проверяется;
- тесты, уже назначенные этому получателю, пропускаются (`alreadyAssigned`), неопубликованные считаются в `notPublished`.

Назначение не связывает набор с ребёнком навсегда: тест, добавленный в набор позже, сам не назначится. Набор можно назначить повторно — уже назначенное пропустится.

## Где это видно

| Место | Что показывает |
| --- | --- |
| Админка → Sets | создание, переименование и удаление наборов; добавление тестов из библиотеки и перенос между наборами |
| Админка → Assignments | каталог тестов ребёнка сгруппирован по наборам, у набора — «Assign whole set (N)»; в форме группы можно выбрать набор |
| Home ребёнка | карточки виджетов Continue и New tests подписаны названием набора; название ведёт на страницу набора |
| Страница предмета | «All tests» разбит по наборам, заголовок набора ведёт на его страницу; тесты без набора — в «Other tests» |
| Tests | карточки наборов (`SetCard`): описание, «сдано из назначенных», сколько в процессе и новых, кнопка Open set; ниже — тесты без набора. Поиск, фильтр предмета или состояния показывают найденные тесты таблицами по наборам |
| Страница набора `/dashboard/sets/[setId]` | описание, прогресс, «Continue learning» и все тесты набора с фильтрами. Набор одного предмета окрашен в его цвета. Набор без назначенных ребёнку тестов недоступен |

Пока наборов нет, списки выглядят как раньше — одним блоком.

## API

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| `GET` | `/admin/test-sets` | Наборы с тестами: название, предмет, класс, новейшая версия и `publishedTestId` — что будет назначено |
| `POST` | `/admin/test-sets` | Создать набор: `name` (1–100 символов, уникальное), `description` (до 500) |
| `PATCH` | `/admin/test-sets/:id` | Переименовать или изменить описание |
| `DELETE` | `/admin/test-sets/:id` | Удалить набор, не трогая тесты и назначения |
| `PUT` | `/admin/test-sets/:id/tests/:stableId` | Добавить тест в набор или перенести из другого |
| `DELETE` | `/admin/test-sets/:id/tests/:stableId` | Убрать тест из набора |
| `POST` | `/admin/test-sets/:id/assign` | Назначить тесты набора детям или группе |

Ребёнку `GET /api/v1/me/dashboard` отдаёт у каждого теста `set: { id, name } | null` и список `sets` — сводку по наборам, где есть его тесты: описание, предметы, назначено, завершено, сдано, в процессе, не начато, процент сданных. Считают их `groupBySet` и `summarizeSets` из `src/lib/student-progress.ts` по тем же строкам, что и списки, поэтому цифры на карточках и страницах совпадают. В сводку набора входят только тесты, назначенные ребёнку, а не весь набор.

Проверка: `node --test tests/test-sets.integration.cjs`.
