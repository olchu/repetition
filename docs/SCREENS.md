# Экраны и критерии приёмки

## 1. Общие экраны

### Вход

- Поля: логин, пароль.
- Ошибка авторизации не раскрывает, существует ли конкретный логин.
- После входа администратор попадает в админку, ребёнок — на свой dashboard.
- Заблокированный пользователь не получает доступ.

## 2. Кабинет ребёнка

### Dashboard

Показывает:

- приветствие с именем;
- карточки только назначенных ученику предметов (назначаются отдельно от тестов);
- число назначенных и пройденных тестов;
- список тестов со статусом `not_started`, `in_progress`, `completed` или `passed`;
- лучший процент и последнюю попытку, если они существуют.

Действия:

- открыть тест;
- продолжить незавершённую попытку;
- начать новую попытку;
- открыть историю результатов.

### Страница предмета

Показывает сводку и отфильтрованный список тестов только выбранного предмета. Пустое состояние явно сообщает, что назначенных тестов пока нет.

### Страница теста

Показывает название, описание, предмет, класс/возрастную группу, количество вопросов и правила прохождения. Правильные ответы здесь не отображаются.

### Прохождение

- один вопрос на экране;
- варианты ответа доступны клавиатурой и указателем;
- виден номер текущего вопроса и общий прогресс;
- можно вернуться к предыдущему вопросу;
- ответ сохраняется автоматически;
- выход предлагает продолжить позже;
- перед отправкой отображается подтверждение;
- после отправки повторно изменить ответы нельзя.

### Результат

Показывает:

- набранные баллы и максимальные баллы;
- процент;
- `Пройден` или `Не пройден`;
- дату завершения;
- действие `Пройти ещё раз`.

После завершения ребёнок видит правильный ответ и объяснение для каждого вопроса, если объяснение указано в JSON.

## 3. Админка

### Dashboard администратора

- число активных детей;
- число опубликованных тестов;
- последние результаты;
- быстрые действия: добавить ребёнка, загрузить тест, назначить тест.

### Дети

- таблица/список с именем, классом, статусом и общей сводкой;
- поиск и фильтрация;
- создание и редактирование профиля;
- блокировка и восстановление доступа;
- переход в детальную статистику.

### Детали ребёнка

- данные профиля;
- прогресс по предметам;
- назначенные тесты;
- лучший и последний результат;
- история попыток;
- назначение нового теста.

### Загрузка теста

- выбор JSON-файла;
- отображение состояния загрузки;
- список ошибок с путями до полей;
- предпросмотр валидного теста;
- сохранение черновика;
- публикация после проверки.

### Список тестов

- фильтры по предмету и статусу `draft`/`published`/`archived`;
- название, предмет, версия, число вопросов;
- просмотр предпросмотра;
- публикация черновика;
- архивирование опубликованного теста.

### Назначения

- выбор теста;
- выбор одного или нескольких детей либо группы;
- просмотр текущих назначений;
- отмена назначения;
- защита от повторного активного назначения одного теста одному ребёнку.

### Результаты

- фильтры по ребёнку, группе, предмету, тесту и статусу;
- баллы, процент, статус, дата;
- переход к деталям попытки.

## 4. Критерии приёмки первой версии

### Авторизация

- Администратор и ребёнок входят по выданным логину и паролю.
- Роль определяет доступ к маршрутам и API.
- Ребёнок не может открыть admin endpoint даже при ручном вводе URL.

### Импорт

- Валидный JSON создаёт черновик с правильным предметом, вопросами, баллами и порогом.
- Невалидный JSON не создаёт доступный тест.
- Ошибка указывает конкретное поле.
- В опубликованном тесте ребёнок не получает правильные ответы до отправки.

### Назначение

- Опубликованный тест назначается ребёнку или группе.
- Ребёнок видит назначенный тест на dashboard.
- После отмены назначения тест не появляется в новых заданиях.
- История завершённых попыток не исчезает.

### Прохождение

- Ребёнок может начать тест, сохранить ответ, выйти и продолжить позже.
- Отправленная попытка получает один неизменяемый результат.
- Повторная попытка доступна без ограничения числа раз.
- Порог правильно определяет `passed`/`completed`.
- После отправки ребёнок видит правильные ответы и объяснения, если они есть в тесте.

### Прогресс

- Статус карточки меняется после сохранения ответа и отправки попытки.
- Тест засчитывается пройденным только после успешной попытки.
- Прогресс предмета не увеличивается от повторных попыток одного теста.
- Лучший и последний результаты не путаются между собой.

### Безопасность и приватность

- Ребёнок видит только собственные задания, попытки и результаты.
- Баллы нельзя подменить запросом клиента.
- Пароль не возвращается API и не хранится в открытом виде.
- Правильный ответ нельзя получить из ответа API во время прохождения.

## 5. Предлагаемый порядок реализации

1. Модель пользователей, ролей и сессий.
2. Дети, группы и фиксированные предметы.
3. Импорт, валидация и предпросмотр JSON.
4. Публикация и назначения.
5. Прохождение, автосохранение и результаты.
6. Dashboard ребёнка и прогресс по предметам.
7. Админские списки, фильтры и история результатов.
8. Проверка адаптивности и доступности.
