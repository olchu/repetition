# API и модель данных — черновик

Документ фиксирует границу React-клиента и серверной части. Целевой стек первой версии: Next.js и PostgreSQL; способ деплоя и объектное хранилище пока не выбраны.

## 1. Общие правила

- Базовый префикс: `/api/v1`.
- Формат тела и ответа: `application/json`.
- Авторизация: защищённая серверная сессия в `HttpOnly`, `Secure`, `SameSite` cookie; сессия действует 30 дней.
- Все проверки прав выполняются на сервере.
- Время передаётся в ISO 8601 UTC.
- Ошибки имеют единый формат:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Файл содержит ошибки",
    "details": [
      {
        "path": "questions[0].correctOptionId",
        "code": "UNKNOWN_OPTION",
        "message": "Вариант ответа не найден"
      }
    ]
  }
}
```

## 2. Авторизация

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| `POST` | `/auth/login` | Вход по логину и паролю. |
| `POST` | `/auth/logout` | Завершение сессии. |
| `POST` | `/auth/change-password` | Смена собственного пароля. Восстановления по email нет. |

Публичного endpoint регистрации нет. Создание аккаунта ребёнка выполняет администратор.

## 3. Администраторские endpoints

### Дети и группы

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| `GET` | `/admin/children` | Список детей с фильтрами по имени, классу и статусу. |
| `POST` | `/admin/children` | Создание ребёнка и постоянного пароля. |
| `GET` | `/admin/children/:id` | Профиль, прогресс и история попыток ребёнка. |
| `PATCH` | `/admin/children/:id` | Изменение имени, класса и статуса. |
| `DELETE` | `/admin/children/:id` | Удаление ребёнка по правилам хранения данных. |
| `GET` | `/admin/groups` | Список групп. |
| `POST` | `/admin/groups` | Создание группы. |
| `PATCH` | `/admin/groups/:id` | Изменение названия и состава группы. |
| `DELETE` | `/admin/groups/:id` | Архивирование или удаление группы. |

### Тесты

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| `POST` | `/admin/tests/import` | Загрузка multipart JSON-файла и валидация. |
| `GET` | `/admin/tests` | Список тестов с фильтрами по статусу и предмету. |
| `GET` | `/admin/tests/:id` | Метаданные, предпросмотр и версии теста. |
| `POST` | `/admin/tests/:id/publish` | Публикация черновика. |
| `POST` | `/admin/tests/:id/archive` | Архивирование теста. |

Ответ `/admin/tests/:id` может содержать `correctOptionId`, потому что доступ к нему есть только у администратора.

### Назначения и результаты

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| `POST` | `/admin/assignments` | Назначение теста ребёнку или группе. |
| `DELETE` | `/admin/assignments/:id` | Отмена назначения без удаления прошлых результатов. |
| `GET` | `/admin/results` | Результаты с фильтрами по ребёнку, группе, предмету и тесту. |

## 4. Детские endpoints

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| `GET` | `/me/dashboard` | Назначенные тесты, состояния и сводка прогресса. |
| `GET` | `/me/subjects/:subject` | Прогресс и тесты по одному предмету. |
| `GET` | `/me/tests/:testId` | Доступный тест без правильных ответов. |
| `POST` | `/me/tests/:testId/attempts` | Создание новой попытки. |
| `GET` | `/me/attempts/:attemptId` | Получение своей попытки и текущего прогресса. |
| `PUT` | `/me/attempts/:attemptId/answers/:questionId` | Сохранение ответа на вопрос. |
| `POST` | `/me/attempts/:attemptId/submit` | Завершение попытки и расчёт результата. |
| `GET` | `/me/tests/:testId/results` | История собственных результатов по тесту. |

Сервер обязан проверять, что тест назначен текущему ребёнку, а попытка принадлежит текущему ребёнку. После сохранения ответа `PUT /me/attempts/:attemptId/answers/:questionId` возвращает `feedback` с `correctOptionId` и `explanation` только для проверенного вопроса. `GET` попытки восстанавливает эти поля для вопросов с сохранёнными ответами. Непроверенные вопросы не раскрывают правильные ответы до `submit`; после завершения доступен разбор всех вопросов собственной попытки.

## 5. Модель данных

Минимальный набор таблиц/коллекций:

- `users`: `id`, `role`, `login`, `password_hash`, `status`, `created_at`, `updated_at`;
- `children_profiles`: `user_id`, `display_name`, `grade`;
- `groups`: `id`, `name`, `status`;
- `group_members`: `group_id`, `child_id`;
- `subjects`: фиксированный seed-справочник либо enum;
- `tests`: `id`, `stable_id`, `version`, `title`, `description`, `subject`, `grade`, `pass_percentage`, `status`, `question_count`, `content`, timestamps;
- `assignments`: `id`, `test_id`, `child_id` или `group_id`, `status`, timestamps;
- `attempts`: `id`, `assignment_id`, `child_id`, `test_version`, `status`, `started_at`, `submitted_at`;
- `answers`: `attempt_id`, `question_id`, `option_id`;
- `results`: `attempt_id`, `earned_points`, `total_points`, `percentage`, `passed`.

Отдельных таблиц под вопросы и варианты нет. Версия теста неизменяема, поэтому вопросы с вариантами хранятся целиком в JSON-колонке `tests.content`, а `answers.question_id` и `answers.option_id` ссылаются на авторские идентификаторы из загруженного файла (`"q1"`, `"a"`). Подробности и открытые вопросы — в [TEST-STORAGE.md](./TEST-STORAGE.md).

На уровне БД должен быть запрещён результат без принадлежащей ему попытки. Принадлежность ответа текущей версии теста проверяется на сервере при сохранении: вопрос и вариант ищутся в `tests.content`, иначе `422`. Правильность ответа рассчитывается на сервере по зафиксированной версии теста.

## 6. Правила прогресса

- `passed = percentage >= pass_percentage`.
- Тест отображается как `passed`, если есть успешная попытка.
- Для карточки теста сервер возвращает лучший процент, последний результат и число попыток.
- Прогресс предмета рассчитывается по уникальным назначенным тестам, а не по числу попыток. Единица уникального теста — `tests.stable_id`: версии одного теста и личное плюс групповое назначение считаются один раз. Это совпадает с возобновлением попыток и правом на награду.
- Отмена назначения скрывает тест из будущего списка ребёнка, но не удаляет исторические попытки.

## 7. Важные серверные ограничения

- Нельзя доверять присланным клиентом баллам, процентам или статусу.
- Нельзя раскрывать правильные ответы непроверенных вопросов незавершённой попытки. Проверка ответа раскрывает `correctOptionId` только соответствующего вопроса.
- Повторная отправка `submit` должна быть идемпотентной и не создавать второй результат.
- Ответы должны быть ограничены вопросами текущей версии теста.
- Удаление/архивирование не должно нарушать ссылки из исторических результатов.
