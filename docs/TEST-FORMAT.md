# Формат теста и загрузка JSON

## 1. Минимальный пример

```json
{
  "schemaVersion": "1.0",
  "id": "science-plants-01",
  "title": "Растения",
  "description": "Проверка базовых знаний о растениях.",
  "subject": "science",
  "grade": "5",
  "passPercentage": 70,
  "questions": [
    {
      "id": "q1",
      "text": "Что нужно растению для фотосинтеза?",
      "points": 1,
      "options": [
        { "id": "a", "text": "Свет" },
        { "id": "b", "text": "Только песок" },
        { "id": "c", "text": "Только лёд" }
      ],
      "correctOptionId": "a",
      "explanation": "Свет необходим для фотосинтеза."
    }
  ]
}
```

Полная JSON Schema находится в [`test.schema.json`](./test.schema.json).

## 2. Поля верхнего уровня

| Поле | Обязательно | Описание |
| --- | --- | --- |
| `schemaVersion` | да | Версия формата. Для первой версии только `"1.0"`. |
| `id` | да | Стабильный slug теста: латинские строчные буквы, цифры и дефисы. |
| `title` | да | Название теста. |
| `description` | нет | Краткое описание для карточки и страницы теста. |
| `subject` | да | Одно из: `science`, `geography`, `history`, `mathematics`. |
| `grade` | нет | Класс или возрастная группа в виде строки. |
| `passPercentage` | нет | Порог прохождения от 0 до 100; если не указан, используется 70. |
| `questions` | да | Массив минимум из одного вопроса. |

## 3. Поля вопроса

| Поле | Обязательно | Описание |
| --- | --- | --- |
| `id` | да | Уникальный идентификатор вопроса внутри теста. |
| `text` | да | Текст вопроса. |
| `points` | нет | Целое положительное число; по умолчанию 1. |
| `options` | да | От 2 до 6 вариантов ответа. |
| `correctOptionId` | да | `id` ровно одного правильного варианта. |
| `explanation` | нет | Объяснение правильного ответа. |

Каждый вариант ответа содержит `id` и `text`. Идентификаторы вопросов и вариантов должны быть уникальными в соответствующем массиве. Указанный `correctOptionId` обязан существовать в `options`.

## 4. Правила валидации

Файл отклоняется, если:

- JSON синтаксически некорректен;
- отсутствует обязательное поле;
- присутствует неизвестное поле;
- `schemaVersion` не поддерживается;
- предмет отсутствует в фиксированном списке;
- в тесте нет вопросов;
- у вопроса меньше двух или больше шести вариантов;
- правильный вариант не найден;
- есть повторяющиеся идентификаторы;
- баллы или порог имеют недопустимое значение.

Ошибки должны содержать путь до поля, код ошибки и понятное описание. Валидация должна выполняться на сервере; клиентская проверка служит только для удобства.

## 5. Поведение загрузки

1. Администратор выбирает файл размером в пределах установленного лимита.
2. Сервер проверяет MIME-тип, размер, JSON и JSON Schema.
3. При успехе создаётся `draft` с сохранённым исходным JSON и нормализованными данными.
4. Администратор видит предпросмотр всех вопросов и вариантов.
5. Повторная загрузка того же `id` создаёт новую версию в статусе `draft` и не перезаписывает опубликованную версию.
6. Публикация фиксирует набор вопросов, баллы и порог для будущих попыток.

## 6. Ограничения первой версии

- только один правильный вариант;
- нет изображений, аудио и видео в JSON;
- нет математических формул в отдельном формате;
- нет частичного начисления баллов;
- нет условий ветвления между вопросами.
