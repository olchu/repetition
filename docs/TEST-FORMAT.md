# Формат теста и загрузка JSON

## 1. Минимальный пример

```json
{
  "schemaVersion": "1.0",
  "id": "science-plants-01",
  "title": "Растения",
  "description": "Проверка базовых знаний о растениях.",
  "subject": "science",
  "grade": "5",
  "passPercentage": 70,
  "questions": [
    {
      "id": "q1",
      "text": "Что нужно растению для фотосинтеза?",
      "points": 1,
      "options": [
        { "id": "a", "text": "Свет" },
        { "id": "b", "text": "Только песок" },
        { "id": "c", "text": "Только лёд" }
      ],
      "correctOptionId": "a",
      "hint": "Вспомни, где растения растут лучше: **на солнечном подоконнике** или в тёмном шкафу?",
      "explanation": "Фотосинтез идёт только **на свету**.\n\nРастению нужны три вещи:\n\n- свет,\n- вода,\n- углекислый газ."
    }
  ]
}
```

Полная JSON Schema находится в [`test.schema.json`](./test.schema.json). Что происходит с файлом после загрузки — в [TEST-STORAGE.md](./TEST-STORAGE.md).

## 2. Поля верхнего уровня

| Поле | Обязательно | Описание |
| --- | --- | --- |
| `schemaVersion` | да | Версия формата. Для первой версии только `"1.0"`. |
| `id` | да | Стабильный slug теста: латинские строчные буквы, цифры и дефисы. |
| `title` | да | Название теста. |
| `description` | нет | Краткое описание для карточки и страницы теста. |
| `subject` | да | Slug активного предмета из справочника БД, например `mathematics`. Справочник управляется в админке Subjects. |
| `grade` | да | Класс или возрастная группа в виде строки. При личном назначении тест доступен только детям того же класса; группе его можно назначить независимо от классов участников. |
| `passPercentage` | нет | Порог прохождения от 0 до 100; если не указан, используется 70. |
| `questions` | да | Массив минимум из одного вопроса. |

## 3. Поля вопроса

| Поле | Обязательно | Описание |
| --- | --- | --- |
| `id` | да | Уникальный идентификатор вопроса внутри теста. |
| `type` | нет | `"choice"` — выбор одного варианта (по умолчанию), `"input"` — ответ вводится в поле. |
| `text` | да | Текст вопроса. |
| `points` | нет | Целое положительное число; по умолчанию 1. |
| `options` | для `choice` | От 2 до 6 вариантов ответа. У `input` поле запрещено. |
| `correctOptionId` | для `choice` | `id` ровно одного правильного варианта. У `input` поле запрещено. |
| `correctAnswers` | для `input` | Принимаемые ответы: от 1 до 20 непустых строк. Первый показывается ребёнку как правильный. У `choice` поле запрещено. |
| `hint` | нет | Подсказка в Markdown. Ребёнок раскрывает её кнопкой «Show hint» до ответа. |
| `explanation` | нет | Объяснение в Markdown. Показывается после проверки ответа. |

Каждый вариант ответа содержит `id` и `text`. Идентификаторы вопросов и вариантов должны быть уникальными в соответствующем массиве. Указанный `correctOptionId` обязан существовать в `options`.

### Вопрос с полем ввода

```json
{
  "id": "q2",
  "type": "input",
  "text": "Росток вырос с 1,5 см до 3,8 см. На сколько сантиметров он вырос?",
  "correctAnswers": ["2.3"],
  "explanation": "3,8 − 1,5 = **2,3** см."
}
```

Ответ ребёнка сравнивается с каждым элементом `correctAnswers` (`src/lib/grading.ts`):

- пробелы по краям и повторные пробелы, регистр букв и разница `ё`/`е` не важны;
- если принимаемый ответ — число, ответ ребёнка сравнивается **как число**: разделителем дробной части может быть и точка, и запятая (`2.3` = `2,3`), лишние нули не важны (`2.30` = `2.3`), пробелы между разрядами допустимы (`1 000` = `1000`); текст вместо числа — неверный ответ;
- иначе ответы сравниваются как текст, но запятая между цифрами равна точке: `3,5 кг` = `3.5 кг`;
- другие формы записи перечисляются отдельными элементами: `["1/2", "0.5"]` — простые дроби как числа не распознаются.

Числа в `correctAnswers` записываются строками: `"2.3"`, а не `2.3`.

### Markdown в `hint` и `explanation`

Оба поля — обычные строки JSON, которые отображаются как Markdown. Перенос строки записывается как `\n`, пустая строка между абзацами — как `\n\n`.

Поддерживается CommonMark плюс GitHub-расширения (GFM):

- `**жирный**`, `*курсив*`, `~~зачёркнутый~~`;
- списки маркированные и нумерованные;
- `` `код` `` и блоки кода в тройных обратных кавычках;
- ссылки `[текст](https://example.com)` — открываются в новой вкладке;
- цитаты `> …`, горизонтальная линия `---`, заголовки `#`–`####`;
- таблицы GFM (при нехватке ширины прокручиваются по горизонтали).

Сырой HTML **не** обрабатывается: теги в тексте выводятся как обычные символы. Это сделано намеренно, чтобы загруженный файл теста не мог вставить разметку в страницу.

Подсказка не должна раскрывать правильный ответ: она приходит клиенту вместе с вопросом, ещё до того, как ребёнок ответил.

## 4. Правила валидации

Файл отклоняется, если:

- JSON синтаксически некорректен;
- отсутствует обязательное поле;
- присутствует неизвестное поле;
- `schemaVersion` не поддерживается;
- предмет отсутствует в справочнике БД или архивирован;
- в тесте нет вопросов;
- у вопроса с выбором меньше двух или больше шести вариантов;
- правильный вариант не найден;
- у вопроса `input` нет `correctAnswers`, список пуст или содержит пустую строку;
- у вопроса есть поля другого типа (`options` у `input`, `correctAnswers` у `choice`);
- есть повторяющиеся идентификаторы;
- баллы или порог имеют недопустимое значение.

Ошибки должны содержать путь до поля, код ошибки и понятное описание. Валидация должна выполняться на сервере; клиентская проверка служит только для удобства.

## 5. Поведение загрузки

1. Администратор выбирает файл размером в пределах установленного лимита.
2. Сервер проверяет MIME-тип, размер, JSON и JSON Schema.
3. При успехе создаётся `draft`: поля верхнего уровня ложатся в колонки таблицы `Test`, а вопросы с вариантами — целиком в JSON-колонку `Test.content`. Отдельных таблиц под вопросы и варианты нет: версия теста неизменяема, поэтому документ и есть источник правды.
4. Администратор видит предпросмотр всех вопросов и вариантов.
5. Повторная загрузка того же `id` создаёт новую версию в статусе `draft` и не перезаписывает опубликованную версию.
6. Публикация фиксирует набор вопросов, баллы и порог для будущих попыток.
7. Ответы ребёнка (`Answer`) ссылаются на `id` вопроса и варианта из самого файла (`"q1"`, `"a"`), а не на внутренние идентификаторы БД; для вопроса `input` вместо варианта хранится введённая строка. Версия неизменяема, поэтому ссылка остаётся валидной навсегда — но и `id` в опубликованной версии менять нельзя.

## 6. Ограничения первой версии

- в вопросе с выбором только один правильный вариант;
- в вопросе с вводом нет допусков для чисел (±0,1), диапазонов и отдельного поля единиц измерения;
- нет отдельных полей для изображений, аудио и видео; картинку можно вставить только Markdown-синтаксисом `![](…)` внутри `hint` или `explanation`;
- Markdown работает только в `hint` и `explanation`; `text` вопроса и вариантов — обычный текст;
- нет математических формул в отдельном формате;
- нет частичного начисления баллов;
- нет условий ветвления между вопросами.
