# Предметы и иконки

Единый справочник — таблица `Subject` в PostgreSQL. Админка → Subjects позволяет создавать
предметы, менять название, иконку, цвета, порядок отображения и архивировать.
`src/lib/subjects.ts` содержит только тип ответа и валидацию полей, без списка предметов.

Поля: `id` (постоянный первичный ключ), `slug` (уникальный неизменяемый код для URL и JSON),
`name`, `icon` (путь к существующему файлу в public/icons или null), `color`,
`backgroundColor`, `textColor`, `sortOrder`, `archived`, временные метки.
Цвета хранятся как #RRGGBB. Интерфейс получает их через `GET /api/v1/subjects`;
`SubjectsProvider` передаёт названия и иконки компонентам и задаёт CSS-переменные по slug.
Названия, цвета и иконки не дублируются в коде и в отдельных тестах.

Имена файлов `phisics.png` и `spain.png` намеренно сохранены.
Прежние `science` и `history` поддерживаются для совместимости с существующими тестами;
для них используется стандартная иконка книги, поскольку отдельные изображения не предоставлены.

Предметы назначаются **отдельно от тестов**, в Children → Subjects → Save subjects.
`ChildSubject` хранит связи ученика с предметами (childId → ChildProfile.userId,
subjectId → Subject.id), порядок и дату назначения. Пара childId/subjectId уникальна.
Новые и существующие ученики без явных
назначений имеют пустой список; миграция не выводит назначения из тестов.
API создания/изменения ученика принимает `subjects` — упорядоченный массив slug из справочника;
пустой массив снимает все назначения, отсутствие поля сохраняет прежние назначения.
Дашборд показывает только назначенные предметы, даже если по ним пока нет тестов.
Назначенные тесты и результаты сохраняются независимо от списка предметов.

`Test.subjectId` — обязательный внешний ключ на Subject. Попытки, результаты, назначения
тестов и награды получают предмет через тест; отдельных дублирующих связей у них нет.
Удаление используемого предмета запрещено внешними ключами. API удаления предмета не предоставляется.

Архивный предмет сохраняет свои тесты, историю и прежние назначения ученикам. Существующий
тест остаётся доступен по правилам назначения. Архивный предмет нельзя заново назначить
ученику или указать при новом импорте. При сохранении списка прежнее архивное назначение
можно оставить или снять. Переупорядочивание сохраняет исходную дату назначения.

JSON импорта сохраняет поле `subject` со slug. JSON Schema проверяет форму строки,
а сервер — существование и активность предмета в БД. Для нового предмета не нужно
менять enum, код или JSON Schema. Slug не переименовывается, чтобы сохранить ссылки и импорты.

Миграция `20260912120000_subject_catalog` создаёт 11 записей (включая science/history),
переносит Test.subject и массив ChildProfile.subjects с сохранением порядка, проверяет
число назначений и только затем удаляет старые enum и колонки. Всё выполняется в транзакции.
Начальный справочник создаётся миграцией; seed администратора не перезаписывает оформление.

Проверки: `node --test tests/subjects.integration.cjs tests/subjects-migration.integration.cjs`.
Нужны PostgreSQL из DATABASE_URL, а для теста миграции — psql и право создавать временную схему.
Первый тест создаёт уникальные записи и удаляет их; второй использует отдельную случайную схему.
